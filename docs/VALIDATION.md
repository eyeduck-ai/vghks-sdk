0.16.0 改善：巢狀表格不再漏主表；離線分析支援 MIS 的 USR_ID SSO 欄位及合法空門診入口；測試參數可配置；NO_SAMPLE／COMPLETED_WITH_GAPS 分離沒有候選的情況；原子門診抽樣涵蓋七天。

0.17.0 新增就診搜尋 SDK、合成測試與離線解析，當時未重建自用 EXE；後續以 visits 計畫補足新增分支的內網驗證，既有其他模組不需重跑。

0.17.1 的 `visits` 增量測試已有內網回傳：必要登入、病歷號查詢、基本資料自動取得身分證、四欄篩選及一筆門診的 SOAP／醫囑成功。身分證分支誤報 PRQ_PATIENT_ID_MISMATCH 後，測試器使用 mrn_fallback 繼續，這些成功不能算成身分證分支成功。

0.17.2 修正病人標頭的 `&hidno=...` URL 片段辨識，後續內網回傳為 COMPLETED_WITH_GAPS。此次身分證與病歷號清單完全一致，SOAP／醫囑明確取自 national_id 來源；唯一缺口是醫師卡號篩選缺樣本。TLS 初始探測失敗均已由相容模式恢復，憑證驗證保持開啟。這些已成功的路徑不需為相同缺卡號樣本再跑一次。

本機離線分析已將 NO_SAMPLE 從錯誤根因移至獨立缺口表，保留原始執行狀態；真正的回應解析錯誤仍需處理。此報告分類修正不改變已測成功的內網請求流程。

0.18.0 將已知相容模式納入 SDK 預設，並把自動切換／憑證備援放進共用傳輸層。localhost 驗證涵蓋：直接使用公開 Service 登入及兩條就診查詢、相容模式第一個請求成功、TLS 1.3 切換、限定來源的憑證備援與嚴格模式、Cookie 保留、匿名探測及 POST 僅送一次、重試證據的離線分類。這些變更不要求為缺少醫師卡號樣本重跑全部內網功能；日後實際回傳可補充新連線策略的現場證據。

驗證層級必須分開：合成單元測試 → HAR／ZIP 只讀重解析 → localhost EXE → 真實內網回傳。後三者依序提供不同證據，不能互相替代。成功 HTTP status、解析成功、取得正文、取得二進位、正文數值完整性也不是同一件事。
